店小谋 Loop 评分标准 v2

每一轮回答四个问题：有没有踩红线，效果多少分，花了多少，这个分数能不能信。四个都有答案，loop 就能自己决定下一步。

草案，还没写进知识库 这一版还没有任何实测分数

范围：经营诊断、账号档案、chatbot 对话、发布后数据复盘，以及复盘之后档案怎么改。不评脚本和视频。上一版（v1）在这里。

四个部分

红线4 条

一票否决。踩一条，这个案例就不能放行，不管效果分多高。

效果100 分

18 个条目、54 个是非检查点。另有一个盲比指标，和强模型做的基准比。

成本4 项

钱、时间、老板的负担。单独一张表，不和效果分混在一起。

可信度6 项

查分数本身靠不靠得住。不过，这一轮的分数不算数。

  1. 跑测试扮演老板按卡对话，再喂三周模拟数据
  2. 过红线逐案例判过或不过
  3. 算效果和成本检查点通过比例，加费用和耗时
  4. 查可信度判分稳不稳，有没有刷分
  5. 自动决策放行、继续改、回退或停下叫人

产品自己的闭环

复盘不是终点。复盘的结论要回到账号档案，档案改完再发、再复盘。标准按这条链评，一个画像连着走三周。

  1. 诊断定主痛点和成功指标
  2. 档案第 1 版定位、栏目、节奏、承接
  3. 发布一周没有真实数据，用模拟数据
  4. 复盘下结论，说清档案要不要改
  5. 档案下一版按复盘改，只改该改的
  6. 回到第 3 步连走三周

账号阶段

档案能改多大，看账号在哪个阶段。档案里要写明当前阶段。

试水期

可以放开试

刚开号或刚接手，还没找到有效的栏目。换栏目、换定位都可以，只要写明依据。

稳定期

不适合大改

已经有栏目连续两周以上带动目标指标。只做小改（承接、节奏、栏目排期）；改定位、主痛点或成功指标，要两周以上的证据，并且老板点头。

两个阶段怎么划界是我的草稿：发满 10 条，且有栏目连续两周目标指标不低于基线，算进入稳定期。模拟数据里先按画像定：已有作品的轻食乙、素食自助丁算稳定期，其余四家算试水期。

现在的产品里这条回路是断的：我在生成档案的两个代码文件里没有找到读取复盘结果的地方。所以第一轮 E 维度预计接近 0 分，这正是 loop 要先补的。

红线

原来的 G1「不知道的不猜」已降成扣分项，放进 A4。剩下四条不计分。和效果条目查的不是同一件事：红线查「做了不该做的」，效果条目查「该做的做到了多少」，同一个毛病不会扣两次。

  • G2地基不能是猜的
    只管三处：主痛点的原因、档案定位的依据、复盘的结论。这三处如果是产品自己推出来的，要带「可能」或标成假设，并写明怎么验证；说成确定的事实就踩线。其他地方的推断不管，产品可以说得果断一点。
  • G3缺关键事实时不下确定结论
    列出未知项，以及谁补、补什么。
  • G4不用平台禁用的宣传说法
    老板自己说的说法可以照用，两种情况除外：属于抖音平台禁用的类别（见下面的清单）；和已知事实相反（说了是冻品，不写鲜切）。出镜和拍摄条件不在红线里：产品可以提出和老板说法不同的建议，只要说明理由，归 B3 评。
  • G5闲聊内容不变成经营建议
    产品不能主动从星座、笑话这类离题话题推出出镜、栏目等建议。老板自己提出想这么做时，产品可以接着做。

平台禁用清单

按你定的口径：平台不禁的都可以用。抖音没有公布完整的禁用词表，官方规则只写了禁用的类别和少量举例，所以清单按类别列。

每个条目拆成几个只能答「是」或「否」的检查点。条目得分等于通过的检查点比例，再对所有案例取平均。标「结果」的条目直接对照答案判：A、B 对照扮演卡，D、E 对照模拟数据的剧本答案。查的是做对没有，而不是做了没有。

每个检查点另外标了「业务」或「模型」。同一个条目里两种问题分开看：业务看判断对不对（痛点、方案、复盘结论、档案怎么改），模型看做事靠不靠谱（记不记得住、丢没丢信息、守不守规矩、说话清不清楚）。两种分的修法不一样：业务分低要改产品逻辑和知识库，模型能力分低要改提示词、结构或换模型。看板上两种分法都显示：按环节五条线，加业务分和模型能力分两条线。按现在的标法，100 分里业务占 68 分，模型能力占 32 分。

A 经营诊断 · 28 分
  • A1痛点判对了14 分 · 结果
    对照每个画像的「真实主痛点」答案。判错了，这一条直接 0 分。
    3 个检查点
    • 业务定出的主痛点和答案一致。不一致则整条 0 分，下面两点不再看
    • 业务只定了一个最高优先问题，其余进待处理
    • 业务店里接不住客时，先处理接不住的问题
  • A2下结论时信息够用7 分
    该问的问到了，又没被可选项卡住。
    3 个检查点
    • 模型给方案前拿到了七项：地区、行业、主营、客单、当前问题、能不能出镜、什么时候能拍
    • 业务扮演卡「被问到才说」里会改变方案的事实，问到的比例（按比例计）
    • 业务没有因为团购等可选项没答就不给方案
  • A3没有白问的问题5 分
    每个问题都会改变一个决定。
    3 个检查点
    • 模型问营业额、成本、能不能出镜这类老板可能不想答的问题时，说了为什么问
    • 业务没有答了也不改变任何建议的问题
    • 模型没有反复追问同一件事
  • A4判断能追到来源2 分
    方便我们自己查错。只要求内部记录，给老板看的文字不用标。
    3 个检查点
    • 模型缺的信息标成了未知，没有自己填猜测值
    • 模型内部记录里，每条关键判断标了来源
    • 模型回到对话原文核对，来源确实支持这条判断
B 账号档案 · 22 分
  • B1老板说过的话没丢4 分 · 脚本
    记下来就行，采不采纳由产品定。脚本逐项比对，不靠判断。
    1 个检查点
    • 模型老板确认过的特色、限制、产能、目标，在档案里找得到的比例（按比例计）。以后接上抖音或美团的接口，从接口拿到的店铺信息也算进来
  • B2方案对得上痛点9 分
    档案是为诊断定的那个问题服务的。
    4 个检查点
    • 业务定位和栏目服务于诊断定的主痛点
    • 业务成功指标是这个痛点对应的指标，不是播放量
    • 业务目标客群没有被泛化成所有人
    • 业务有这家店自己的东西：定位或栏目里至少用到一样老板说的特色、位置、老顾客或年头，不是全套通用模板
  • B3老板能照做9 分 · 结果
    对照扮演卡上的设备、人手、时间，判方案做不做得了。发得多不等于要老板天天拍。
    4 个检查点
    • 业务给老板的每项任务，在扮演卡写的设备、人手、时间条件下做得了
    • 业务发布节奏、出镜、拍摄时段和老板说的不一样时，写明「你说过 X，我们建议 Y，因为 Z」，并给出按老板现有条件也能开始的最低版本
    • 业务发布次数多于老板能拍的次数时，安排集中拍摄：一次拍完、传完素材，够后面多条用，老板不用每天管
    • 业务扮演卡「陷阱」表里适用于档案的条目，按正确做法处理的比例（按比例计）

  • D1结论判对了5 分 · 结果
    对照剧本答案，判复盘下的结论对不对。
    3 个检查点
    • 业务盯的是诊断定的成功指标，带基线和时间窗口
    • 业务结论状态和剧本答案一致（主问题未明确、未执行或执行偏差、证据不足、可继续观察、触线暂停）

  • D2结论有边界3 分
    不把观察说成因果。
    3 个检查点
    • 业务没有对照时，不说「因为这条视频」
    • 模型老板口述的数据标了「未核实」
    • 模型写了「仍不知道什么」
  • D3说清档案要改什么3 分
    复盘要给档案一个明确的交代。
    3 个检查点
    • 模型明确写了档案哪一项要改，或者写明不改
    • 模型每个改动都指到一条数据或观察
    • 业务一次只提一个主要改变
  • D4定期问老板经营现况4 分
    数据只说了一半，另一半要问老板。每周复盘前问一次，最多 3 个问题。

    • 业务每周复盘前问了老板这周的经营情况，问题不超过 3 个
    • 业务目标指标连续上涨时，问了老板视频帮了多少（有没有客人说是刷到视频来的）
    • 业务播放涨而目标指标没动时，先问老板目标指标的实际变化，再下结论
    • 模型老板的回答记进了复盘，并标了「口述未核实」

盲比 · 第二个头部指标

和基准比，老板拿到哪份更有用

先用强模型（Opus 5.5，推理开最高）给每个画像做一份我们认可的诊断和档案，当作基准。每轮把产品的输出和基准去掉标记放在一起，让判分模型选「老板拿到哪份更有用」。记录产品不输给基准的案例比例。它用来抓检查点没列到的问题：检查点全过但整体不如基准，说明标准漏了东西。

模拟数据

没有真实的发布后数据，所以我编了一套。每份数据是「一个画像配一个剧本」：发布前 4 周的基线，加发布后 3 周。剧本是故意设计的，每个都有标准答案，所以复盘和档案改得对不对可以直接判。

剧本数据长什么样复盘该下的结论档案该怎么动
S1目标指标连续三周上涨，没有外部干扰可继续观察先问老板经营反馈（视频帮了多少），再把数据最好的栏目多排几条；定位不动
S2播放量涨了四到六倍，目标指标没动可继续观察先问老板目标指标的实际变化；确认没动后只改承接，定位不动
S3计划的内容大部分没发未执行或执行偏差把节奏降到老板做得了的量；不评价内容效果
S4某一周目标指标大涨，但同周有外部变化证据不足不动；写出外部变化，下周继续看
S5老板没交截图，只有一句「感觉人多了点」证据不足不动；请老板补一张截图
S6客人多了三到五成，老板说排队走人、出餐慢触线暂停暂停引流内容，走重新诊断
S7目标指标没动，老板改口说问题不在这主问题未明确走重新诊断，之前不改定位和目标
S8混合：内容没发够，同一周又有外部变化未执行或执行偏差先降节奏；那一周的上涨不归因
S9混合：只涨了一周就回落可继续观察不动；单独一周的上涨不算数

一共 50 份：每轮默认跑 27 份，另有 6 份留出集不给产品经理 Agent 和工程 Agent 看。S8、S9 是两种情况叠在一起的混合剧本，防止产品只背前七种套路。目标指标只用知识库认定拿得到的数据：来客后台的核销数、流水照片的人工回填、老板口述。涮肉戊只有口述数据，不参与 S1、S2、S4、S9。

格式按产品来：经营数据和作品数据都是 CSV，表头和产品「数据导入」功能的一致，可以直接上传。我用产品自己的导入校验代码跑了一遍，418 个文件全部通过。产品的导入格式放不下的三样东西（老板口述、外部变化、计划发几条实际发几条），由扮演老板在对话里说出来；其中外部变化设成「被问到才说」，产品不问就拿不到。

文件在 output/dianxiaomou-rubric-v2-20261004/sim-data/：inputs/ 给产品和扮演老板用，answers/ 是标准答案，只给判分用。数字是按规则生成的，涨跌幅度是我定的。产品的导入格式分不出午市和晚市，所以轻食乙的目标指标先用整周核销数。

    从建档到出档案，产品自己调模型花的钱。
  • K2每个案例的耗时分钟
    老板从开始对话到拿到档案等了多久。
  • K3老板的负担问题数
    说出主痛点之前，老板回答了几个问题。你说的「快速问出痛点」放在这里量，不再按轮数扣效果分。
  • K4每轮 loop 的开销元、小时
    跑测试、判分、改代码、重评，一整轮花的钱和时间。

预算现在定不了，因为还没量过。第一轮实测值当基线，预算先按基线的 1.2 倍。

可信度

前五项由机器完成，loop 不停下来等人。第六项是你每轮看一个案例，大约 10 分钟。

  • T1基准自己要过关基准 ≥ 90 分
    强模型做的基准用同一套标准打分，要过全部红线且到 90 分。到不了，说明基准或标准有一个是错的，先修再开跑。
  • T2判分要稳一致率 ≥ 80%
    每个案例判三遍。三遍结果不一致的检查点标出来，不计分，回头把它写清楚。
  • T3判分和生成分开不同模型
    判分模型不是产品用的模型，看不到改动需求，也不知道手里这份是改动前还是改动后的。拿不准时取低分。扮演老板看不到评分标准。
  • T4量出噪声每个画像跑两遍
    同一版本两遍之间的分差就是噪声。涨幅超过噪声才算真的涨了。
  • T5留出集差距 ≤ 10 分
    两个画像对产品经理 Agent 和工程 Agent 不可见。公开画像和留出画像的分差拉大，说明在刷分。
  • T6你每轮看一个案例一致率 ≥ 4/5
    看板每轮挑一个案例给你，你对每个检查点点「同意」或「不同意」。记下你和判分模型的一致率；你不同意的地方用来修标准。一致率明显下降时停下，不再按机器分数选改动。

每轮自动决策

放行

过了放行线

红线零阻塞，每维 ≥ 90，总分 ≥ 90，盲比不输率 ≥ 50%，留出集差距 ≤ 10，成本在预算内。过线后不停，继续往 100 分改。

继续改

没达线，但可信度过了

从没过的检查点里选 1 到 3 个预期涨分最多的改动，工程 Agent 改完，同一测试集重评。

回退

改了反而变差

任何条目的跌幅超过噪声，或出现新的红线，撤掉这次改动。

停下叫你

机器定不了

连续三轮涨幅没超过噪声；可信度连续两轮不过；成本连续两轮超预算；或改动要动数据库、部署、产品方向。

目标是 100 分，放行线只是「可以拿给人看」的最低要求。每轮结束把学到的东西写回知识库。标准本身改了，就用新标准把之前各轮重算一遍，曲线才可比。
