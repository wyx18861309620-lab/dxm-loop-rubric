用 AI 团队从零建一家公司

通用版公司手册 · 不针对某一个项目 · 从店小谋 10 月踩过的坑里总结 · 2026-10-27 初版

零 原则一 第一天建什么二 组织三 模型怎么选四 一件事怎么走五 硬规矩六 钱和账号七 和老板怎么说话八 常见坑九 第一周

零 · 三条原则

  1. 老板只做只有老板能做的事：定方向、拍板、付钱、点头上线、对外签字。其余一切交给 agent，能写成脚本的写成脚本。
  2. 做的人不验自己：写代码、派活、验收、上线是四个不同的人。验收的人独立，只有它能说「上了」。
  3. 坑踩一次就变成机器检查：每出一个新问题，当天写成一条自动测试或闸门检查，不靠人记、不靠人再看一遍。

一 · 第一天就要建好的 10 样东西

项目还没开工就建好。少一样，后面一定以事故的形式补回来。

东西做什么用谁维护
任务看板（公网可看）每件事一行，带进度条、负责人、卡在哪；老板不问进度，看它总经理，每件事一变就更新
组织图（公网可看）谁负责什么、用什么模型，点队名看该队进度总经理，组织一变当场改
公司手册（本页）所有现行规矩只有一份；新会话开工先读总经理，规矩一改同时改
老板原话记录老板每次拍板的原话 + 时间；后来的推翻前面的总经理，只追加
经验库每个坑：哪天、什么事、硬检查是什么、本来能挡住哪次各岗位，每件事做完写一条
账户与预算表每个外部账户：谁的、月预算、余额、续费日、告警线管钱 agent
测试账号池一批假号，各有用途（有数据的、空白的、专给自动检查的）；密码只在本机文件上线组开，验收方用
代码仓库 + 整车闸门类型检查、全量测试（超时算红）、构建、走查、迁移顺序、包含线上版本装车
部署脚本先等空闲再重启、整目录换、留上一版可一键回退、部署不断服务上线组
上线后冒烟脚本一条命令、两分钟内、不调大模型、只读，每次部署后跑验收方

二 · 组织

按用户走的路分队，不按技术分

把用户从进来到拿到结果的路切成几段，每段一个业务小队（例：进门建档 → 准备材料 → 生成方案 → 产出交付）。一个队从页面到后台全包，跨队的接口写成书面约定。

岗位

岗位做什么不做什么
总经理收老板的需求、定规则、分到队、拍板队里定不了的事、向老板汇报、维护看板 / 组织图 / 手册不写代码，不部署
业务队长（每队一个）定本队做什么、写简报派给写代码的、审交回来的东西、交号不写代码，不说「上了」
写代码的照简报和《工程规矩》写代码、写测试（先红后绿）、写交接说明不部署，不推共享分支
装车（脚本）每 15 分钟收号、合车、跑整车闸门，过了写进待上线，没过退回并写清原因不改业务代码
上线组唯一能动线上：部署、开关、数据库、外部机器、测试账号；线上出事第一个查不写功能代码
验收（用户测试）每车上线后，只验改动的路径各 3 遍，过了才标「上了」；落成脚本反复跑不修 bug，只报
监工每 5 分钟看一遍谁在偷懒、谁卡住、谁越界，只报给总经理不派活，不催人
管钱盯所有账户余额、用量、额度，快用完提前报，每天早上报总表不充值，不改配置

单点要有替补

装车、上线这种一停整条线就停的岗位：交接只写文件不靠消息；急修号写进固定文件，谁活着谁就能接着上。

三 · 模型怎么选

活的性质用什么例子
要判断、要和人沟通、出错代价大最好的模型总经理、队长、上线组
写代码（任务切小、规矩写清）便宜快的写代码模型所有功能和修复
照规矩办事、不需要思考写成脚本 + 便宜模型兜底装车
只看只报最便宜的模型监工、管钱

换模型前先拿一个真实的小活做对比（用时、用量、测试过没过、代码质量），再换。便宜模型一次给大活容易做一截就停、还会虚报「测试过了」：一项一派，每项只要一个可验证的结果，派活的人自己重跑一遍。

四 · 一件事从想法到上线

老板提需求→总经理记原话、画示意图→老板点头定稿→分到队→队长写简报→写代码 + 先红后绿的测试→交号（写文件）→装车 + 整车闸门→上线组部署→冒烟→验收按改动走 3 遍→看板标做完→坑写进经验库
  • 示意图没定稿，不拉工程。定稿后一次交接，不边改边转。
  • 「上了」= 验收方在线上照定稿逐项核过。没核过只能说「已部署，待验收」。
  • 出了问题先止血（回退或关开关），再查根，再修；回退只退代码，不动数据。

五 · 硬规矩（所有岗位）

  1. 没当场跑过，不许说「过了 / 修好了 / 做完了」；说的时候附命令和结果。
  2. 修 bug 先写一条会红的测试，改完变绿；不放松原有断言。
  3. 调用外部服务（存储、模型、第三方网页）的代码，上线前在测试账号上真跑一次；假接口不算。
  4. 失败不能记成「确实没有」：失败要冷却后重试。
  5. 请求里起的后台活不能挡住响应，要有一条「后台永远不回、接口照样马上返回」的测试。
  6. 每次读数据都带上客户 / 门店编号，不跨客户读；不用真客户的账号测试。
  7. 密码、key、token 不进日志、不进消息；外露一次就换。
  8. 只有上线组动线上；部署前核「车头包含当前线上版本」；闸门测试超时算红。
  9. 改「首屏读哪些数据」「每条都要算一遍」的东西，用数据多的、少的、有在途任务的三种账号验。
  10. 换产出引擎 / 模板 / 配音，验收同时看画面、听声音、核时长。
  11. 不往别人的窗口里打字；会话之间只用消息或文件。
  12. 规矩改了，当天同时改手册、组织图、看板；过时的说明比没有说明更害人。

六 · 钱和账号

  • 每个外部账户（模型、云、存储、配音）开户时就登记：属于谁、月预算、充值方式、告警线。
  • 管钱 agent 每天报一次：余额、昨天花了多少、还能撑几天；撑不到 7 天就提醒老板充值。
  • 线上模型调用失败率 5 分钟超过一半，立刻告警，并分清是余额、限流还是别的。
  • 按客户设上限（如每家每月多少钱），全局上限只当保险，不让它先关闸。
  • 任何会花钱的评测、批量任务，先拿到老板原话，记下来再跑。
  • 只有一个模型供应商是风险：至少备一个能切过去的供应商，并定期验它能用。

七 · 和老板怎么说话

  • 先结论，再要他定的事；一次最多三问，每问给 A / B / C 和推荐。
  • 不发工具调用、文件路径、术语；一件事一句人话。
  • 他看不到的东西不算交付：要看的都发公网链接或截图。
  • 说错了当场更正，说清楚之前哪句不对、为什么。
  • 他提的痛点，当天落成规矩并告诉他记在哪。

八 · 店小谋 10 月踩过、换任何项目都会再踩的坑

坑后来的硬检查
模型账户余额用完，线上 AI 停了 20 多小时没人提前知道管钱 agent + 失败率告警 + 备用供应商
装车和上线的会话额度同时用完，修好的急修多等 15 小时交接写文件、急修文件谁活着谁上、照规矩的活改脚本
做的人自己验，「上了」说了好几次又收回只有独立验收方能说上了
一个队担子太重，大部分 bug 都出在那里按用户路线把大队拆开
换了引擎只看画面没听声音，出的片全是静音产出类改动验画面 + 声音 + 时长
失败写成「没有」且不再重试，坏数据变永久失败冷却重试
后来的车冲掉先上的车部署前核包含线上版本
测试挂住，闸门半小时不出结果测试超时算红
规矩改了，说明文件没改，有人照旧规矩办事规矩一改，手册 / 组织图 / 看板同时改
密码被写进日志两次共用日志函数先抹敏感字段，外露即换

九 · 新公司第一周

时间做什么
第 1 天开总经理会话；建看板、组织图、手册、原话记录、经验库；登记所有外部账户和预算；开管钱 agent
第 2 天仓库、闸门、部署脚本（不断服务 + 回退）、冒烟脚本；开上线组；开测试账号池
第 3 天画出用户路线，切成业务小队；每队开一个队长；写《工程规矩》附给写代码的
第 4 天装车脚本、验收方、监工到位；第一件小功能走完整条流程，当演练
第 5–7 天按看板推进；每天早上管钱报表、晚上把当天的坑落成检查；周末对着手册删掉不再用的规矩
